# Step 5：实际预算动作成本筛查

日期：2026-10-26。用户要求：“按你建议的推荐顺序进行吧”。

本轮执行推荐顺序的第一项：辨别可避免的实际工作，并对已有实际请求做成本空间
筛查。没有新检索、索引构建、策略拟合、阈值调优、SSH或角色开启。
本文件是L1开发诊断，不是新科学协议或部署授权。

## 结果与推进决定

**保留批量Tri优化；当前动作空间未证明有足够的付费收益，不进入收益模型训练
和选择性Tri消融。** 这里区分“成本模型已明显不利”和“新增特征成本尚未测量”：
后者不被写成已失败，也不被写成已通过。

| 分组与质量要求 | 免费完美决策，搜索前选一次动作 ms | 先pilot再完整重搜 ms | 最强对照 ms |
|---|---:|---:|---:|
| 旧ANN Tune2048，retention>=.90、Hit delta>=-.02 | 2.033442 | 2.044292 | 2.132357，查询无关预算混合 |
| 同一旧ANN分组，匹配原空间ANN64实际质量 | 9.798771 | 10.607640 | 2.269398，原空间ANN64 |
| 精确Selection256，retention>=.90、Hit delta>=-.02 | 620.258202 | 697.800156 | 623.086876，查询无关预算混合 |

第一列oracle甚至不付pilot与特征费，是不可直接部署的乐观下界。第二列支付
完整pilot和完整后续调用，但仍假设信息免费且决策无误。表中均是从旧实际调用
均值构建的成本模型，不是新流水线计时；不同分组的绝对毫秒数不能横向比较。

## 1. 哪些动作确实改变工作量

- 精确机制v1：每查询先扫描全库并取最大256，再选择重排前缀；停止不会省去
  已完成的扫描和最大候选选取。此前该布局的成本问题仍成立。
- 当前HNSW实现：每次search(k)设置efSearch=max(256,2*k)。请求64/256/1024/4096
  分别对应efSearch256/512/2048/8192。停止可以避免更宽图搜索、候选精算与重排。
- 扩展会重新启动HNSW，不存在已保存的遍历状态复用。两次调用都必须计费。
- 在现有ef_floor=256下，将返回M从64缩到32并不会降低配置的搜索宽度；不能
  未经测量就把较小返回数当作按比例减少图搜索。

本轮没有改efSearch或网格，也没有用截断大M轨迹伪造小M调用。

## 2. 可核查的成本与质量口径

分析入口：[analyze_tls_rag_step5_action_costs.py](../scripts/analyze_tls_rag_step5_action_costs.py)。
证据：[JSON结果](step5_action_cost_screen_evidence.json)。

输入仅为已开放记录：旧Tune2048的已校验compact包，以及机制Selection256的
既有质量与固定策略计时。读取固定文件名并核对SHA，不扫描其他角色或旧保护档案。
两个分组分别计算，未混合总体、硬件或缓存条件。

每个动作的成本取该动作实际完整调用的分组均值；所有查询使用相同的动作成本。
oracle只能利用真实质量，不能通过挑选某查询一次测量中偶然最快的动作获益。
retention以top10邻居计数、Hit以0/1计数建立整数约束。
本次目标是调用毫秒数，不是最少候选；最优预算分布可能不同于此前的候选数oracle，
并不替换或修改原候选数诊断。

比较两种信息/动作模型：

1. **搜索前免费oracle**：提前知道结果，在已有固定调用中只执行一个。
   不包含获取这种信息的费用，所以只是极端乐观的成本下界。
2. **pilot后完整重搜**：先执行最小预算完整调用；扩展时再执行一个完整调用，
   返回后者结果并丢弃pilot候选。成本为两次完整调用之和，包括各自评分和重排。
   它复用的是“已有完整调用的质量记录”，没有假定ANN候选嵌套。

第二种动作与旧实验的persistent union不同。其结果只能作为新候选动作的成本
模型，不能写成旧persistent策略的已测表现；若实现该动作，需新的明确修改范围。
本轮不从compact包缺失的逐阶段Hit推断persistent策略的新质量。

固定对照按既定质量约束筛选；额外加入不看查询的动作概率混合，用线性规划
计算其期望质量与成本。它不需要特征，但同样只是模型中的期望策略，未实际运行。
oracle用二元整数规划，每条查询选一个已有动作；六个问题均达到零MIP gap。

## 3. ANN低质量目标：不是没有收益，而是新增开销预算很小

原质量目标不变：retention>=.90，Hit相对exact>=-.02。

| 对照/候选 | 模型均时 ms | 说明 |
|---|---:|---|
| 固定投影ANN256 | 4.485730 | 原开发目标合格 |
| 原空间ANN64 | 2.269398 | retention=.9958984375，Hit=.76220703125 |
| 查询无关混合 | 2.132357 | 95.451%请求64，4.549%请求256；期望retention=.90 |
| 免费搜索前oracle | 2.033442 | 2037条请求64，11条请求256 |
| 免费pilot后重搜oracle | 2.044292 | 同一最终预算分布；11条支付两次完整请求 |

若只比固定256，会误以为自适应有巨大空间；加入无需查询信息的混合对照，
优势显著缩小。pilot后oracle相对该对照只剩**.088064ms/查询（4.130%）**。

因此，在仍满足质量约束的前提下，所有新增廉价特征、Tri门控、被调用的Tri、
路由与数据准备的平均费用必须小于约88微秒；相对完美分配的动作效率损失还会
继续消耗这个余额。该预算不是只留给概率函数的。

本轮没有把Mac合成特征时间直接代入旧服务器ANN时间；两者不能跨环境相减。
总用优化Tri的真实新增费用和选择性门控可达性均未测量，付费门槛**尚未建立**。
它们不被记为已通过或真实失败。

作为敏感性分析，若未来要求均时至少改善5%，pilot后oracle尚差.018554ms；
即使搜索前所有信息免费，改善也只有4.639%，仍不足5%。5%是讨论中的工程
收益门槛，**不是本次擅自新增的冻结判定标准**。

## 4. 更高质量不是主目标的偷偷替换

额外检查：若要求匹配原空间ANN64已有的retention=.9958984375及Hit=.76220703125，
搜索前oracle也需约9.798771ms，原空间ANN64仅2.269398ms；加pilot则约10.607640ms。
所以当前投影维度和预算动作，在这个质量点即使预测免费也没有成本优势。

这是另列的质量敏感性检查，没有将原来的.90目标改为.9959来宣布原实验失败。

## 5. 精确后端：重新扫描不是合适的扩展动作

精确Selection256中，最好的查询无关混合为约47.170%请求32、52.830%请求128，
模型期望retention=.90，均时623.086876ms。

搜索前免费oracle为620.258202ms，仅剩2.828675ms（.454%）的理论余量。
若先完成pilot32、之后扩展时再完整扫描，oracle也需697.800156ms，已经慢于对照。

这说明现有精确扫描重新请求的动作不值得进入路由器训练。惰性选取/距离数组
复用是另一种执行布局，本轮没有测它；不能据此宣称它不可能，也不能预先将它
记成正收益。其数组写入、内存和选取成本及同样优化的固定对照仍需另行评审。

## 6. 执行到哪里，为什么在这里停止

1. 已完成实际动作和可省工作核对，并完成免费信息成本上限与强对照筛查。
2. 当前精确重新扫描动作以及ANN匹配原空间质量的动作，在成本模型上已不利。
3. ANN在.90目标仍有微小免费空间，但完整付费空间没有正面证据；在建议的5%
   收益敏感性下连免费模型也不够。故不自动训练复杂路由器，不进一步消融Tri。
4. 保留局部数值一致的批量优化及全部负结果，不将它们解释为Tri-Law被否定。

若用户以后明确希望追求约4%以下的理想收益，最小下一步是CPU上的真实输入
特征/门控成本探针，检查完整新增费用是否可能低于88微秒。那不是A800 GPU
计算需求；也不能把原0.5核/2GiB无卡实例当成与原计时等价的环境。新特征实现、
输入访问和运行范围应先按AGENTS提交精确路径方案，本轮未执行。

若要扩大收益空间，应另行评审真正改变搜索工作的动作及公平基线，而不是在
原记录上不断缩网格、换阈值或调efSearch直到得到正结果。尚无对应实际调用的
新动作不能用旧记录伪造结果；进一步真实实验需要新的范围与命名空间。
